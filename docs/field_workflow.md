# ParcelAI Mobile Field Workflow & Active Learning Loop

> **Notice:** *All outputs generated by ParcelAI are Preliminary — subject to field verification.*

## 1. Overview & Architecture

ParcelAI bridges automated drone AI extraction and ground cadastral truth through an open, standards-compliant round-trip workflow using **QField** (the leading open-source mobile GIS app powered by QGIS).

```
┌────────────────────────────────────────────────────────────────────────┐
│                        ParcelAI Web-GIS Platform                       │
│  • AI multi-task segmentation & regularized building footprints        │
│  • Automated hybrid parcel watershed & topology validation             │
│  • Confidence scoring & priority Review Queue                          │
└─────────────────────────────────┬──────────────────────────────────────┘
                                  │
                   1. Export Field Package (GPKG)
                   GET /api/v1/projects/{id}/field-package
                                  │
                                  ▼
┌────────────────────────────────────────────────────────────────────────┐
│                        QGIS / QField Mobile App                        │
│  • Offline vector layers: parcels, buildings, roads, issues, gt_points │
│  • High-accuracy GNSS/CORS RTK positioning integration                │
│  • Form-based attribute survey: verification checkbox, notes, photos   │
│  • Boundary linework adjustment & vertex editing in the field          │
└─────────────────────────────────┬──────────────────────────────────────┘
                                  │
                   2. Field Sync Ingest (GPKG)
                   POST /api/v1/projects/{id}/field-sync
                                  │
```

## 2. Step-by-Step Field Operation Guide

### Step 1: Export Field Package from ParcelAI
1. Open the ParcelAI Web Dashboard.
2. In the top navigation, open the **Export** menu and select **QField Mobile Package (.gpkg)**.
3. Alternatively, invoke the REST endpoint:
   ```bash
   curl -X GET "http://localhost:8000/api/v1/projects/1/field-package" -o project_1_qfield.gpkg
   ```
4. The exported GeoPackage contains 5 structured vector layers:
   - `parcels`: Cadastral boundaries with surveyor verification fields.
   - `gt_points`: Ground-truth checkpoints and GNSS measurement points.
   - `buildings`: Regularized building footprint polygons for orientation.
   - `roads`: Road corridors and centerlines for field navigation.
   - `issues`: Flagged topology violations (overlaps, slivers, gaps) requiring on-site inspection.

---

### Step 2: Open Package in QGIS / QField
1. **Desktop Preparation (Optional):** Open `project_1_qfield.gpkg` in QGIS Desktop.
   - Customize form widgets in *Layer Properties → Attributes Form* if desired.
   - Transfer the `.gpkg` file to the mobile device via USB cable, Nextcloud, or direct file share.
2. **Mobile Field Survey (QField):**
   - Install **QField for QGIS** (free & open-source on Google Play Store / iOS App Store).
   - Tap **Open local file** and select `project_1_qfield.gpkg`.
   - Enable internal GPS or connect an external RTK GNSS receiver via Bluetooth (NMEA mock location).

---

### Step 3: Conducting the Ground Survey
1. **Review Flagged Parcels:**
   - In the QField layer panel, highlight the `issues` layer and low-confidence parcels.
   - Navigate to the property boundary on the ground using real-time GNSS location.
2. **Boundary Verification & Vertex Editing:**
   - If AI boundaries align with physical boundary markers (walls, fences, stones), select the parcel and check `verified = true`.
   - If boundary points require adjustment, toggle **Edit mode** in QField and snap vertices to actual physical fence lines or measured GNSS points.
3. **Capture Surveyor Data & Geotagged Photos:**
   - Fill in surveyor name (`surveyor`), observations (`survey_note`), and attach a ground photo (`photo_url`).
   - Save layer edits.
4. **Capture Ground Control / GNSS Checkpoints:**
   - Switch to the `gt_points` layer.
   - Add a point at surveyed survey monuments or parcel corners.
   - Record RTK horizontal accuracy in meters (e.g., `0.02` for 2 cm accuracy).

---

### Step 4: Syncing Surveyed Data Back to ParcelAI
1. Transfer the updated `.gpkg` file from the mobile device back to your workstation.
2. In the ParcelAI Web Dashboard, click **Upload / Sync → Ingest Field Package**, or use the API:
   ```bash
   curl -X POST "http://localhost:8000/api/v1/projects/1/field-sync" \
     -F "file=@project_1_qfield_surveyed.gpkg"
   ```
3. The ParcelAI backend will:
   - Match modified features by `id`.
   - Update verified parcels to `status="verified"` and `source="field"`.
   - Recompute area (`area_m2`) for modified geometries.
   - Store surveyor name, timestamps, and notes into LADM `ladm_attrs`.
   - Append immutable before-and-after geometry records to `edit_history`.
   - Ingest new GNSS checkpoints into `gt_points`.

---

### Step 5: Active Learning & Fine-Tuning Retraining
To continuously improve the neural network using surveyor corrections:
1. Run the fine-tune dataset extraction script:
   ```bash
   python scripts/build_finetune_set.py --project-id 1 --output-dir data/finetune/ --tile-size 512 --overlap 0.25
   ```
2. The script extracts 512×512 image tiles (RGB + nDSM) intersecting verified parcels and rasterizes ground-verified multi-task masks:
   - `masks/building/`: Verified building footprints.
   - `masks/road/`: Verified road corridors.
   - `masks/boundary/`: Verified parcel property lines (dilated thin edge masks).
   - `masks/landuse/`: 6-class land cover labels.
3. Fine-tune model weights with `ml/train.py`:
   ```bash
   python ml/train.py --config ml/configs/finetune.yaml --resume models/parcelai_v1.pt
   ```
4. Export updated weights using `ml/export_weights.py` to deploy improved models without code changes.

## 3. Data Dictionary & Attribute Specifications

### `parcels` Layer

| Column | Type | Description | Editable in Field |
|---|---|---|---|
| `id` | Integer | Unique Parcel ID in database | No |
| `project_id` | Integer | Project ID | No |
| `confidence` | Float | AI Model confidence score (0.00 – 1.00) | No |
| `status` | String | `draft`, `reviewed`, `verified` | Yes |
| `source` | String | `ai`, `edited`, `field`, `existing` | Auto-updated to `field` |
| `area_m2` | Float | Surface area in square meters | Auto-recomputed on edit |
| `verified` | Integer (0/1) | Field verification toggle checkbox | **Yes (Set 1 to confirm)** |
| `surveyor` | String | Name or badge ID of field surveyor | **Yes** |
| `survey_note` | Text | Observations, disputes, monument notes | **Yes** |
| `photo_url` | String | Path or URL to geo-tagged field photo | **Yes** |
| `survey_time` | String | ISO 8601 timestamp of field survey | Auto-recorded |
| `ladm_attrs` | JSON/Text | Land Administration Domain Model attributes | Auto-merged |

### `gt_points` Layer

| Column | Type | Description |
|---|---|---|
| `id` | Integer | Checkpoint ID (null for new points) |
| `source` | String | `gnss`, `cors`, `field` |
| `accuracy_m` | Float | Positional accuracy from GNSS receiver (e.g. 0.02 m) |
| `note` | Text | Description of physical monument / mark |
| `photo_url` | String | Ground photo of surveyor checkpoint |

## 4. Privacy & Data Security

1. **Strictly On-Premise:** All GeoPackages, high-resolution orthomosaics, and GNSS coordinates remain stored entirely within your local Docker PostGIS instance and mobile device.
2. **No Third-Party Transmission:** No parcel boundaries or surveyor photos are transmitted to external cloud servers or map tile APIs.
